### P10-2 具体做了什么（这一节的根因值得记住）

**根因不是「弹窗文案不好」，是「一个不该存在的确认环节」被写进了三条路径**：手动更新、切换场景、自动模式开关。
所以修法是删源头，不是藏 UI：

| 位置 | 删掉的东西 |
|---|---|
| `studio/index.html` | 整块 `#confirm-modal`（含 `#modal-title/#modal-note/#modal-cost/#modal-foot/#modal-ok/#modal-cancel`） |
| `studio/app.js` | `state.pendingPaid`、`openPaidConfirm()`、`closeModal()`、`regenerateSceneConfirmed()` 以及三处事件绑定 |
| `packages/bridge/src/scenegen.mjs` | `choose()` 的 `requiresConfirm` 分支（现在 `{ confirm = true }` 只表示「用户明确要做」） |
| `packages/bridge/src/server.mjs` | `/api/plans/:id/scene`、`/scene/auto`、`/scene/regenerate` 里的确认分支 |

现在的行为：

- **自动模式开**：换件 → 服务端排一次生成（防抖 + 合并 + 缓存）→ 图上角一条「正在更新穿搭图…」，完成原地换图。
- **自动模式关**：换件只改方案/清单/金额，**不生成、不弹框**，图左上角一条「搭配已更新，图还是上一版 · 更新穿搭图」。
- **手动更新**：点一下直接执行，没有第二个问题。
- **失败**：保留上一版图 + 一条人话 toast（「这次没画成功，先保留上一版图片，可以点重试」）+ 提示条里的重试入口。

**顺手修掉的一个真问题**：换件时服务端广播的 `plan.updated` 没有 diff 也会弹 toast「AI 更新了方案：」，
把用户刚看到的「已换 xx 这一件」覆盖掉（`verify:stage3` D 段因此 flake）。现在只有 `by !== 'ui' && diff` 才提示。

### 关于「弹窗」的边界（本轮把标准拉齐了）

原来图过期/正在生成/生成失败这三种状态都是**一张压在图上的白卡片**，读起来就是在问「要不要生成」。
P10 起统一成**图片左上角的一条轻量状态条**：不压暗、不挡热点点击、没有「确认/取消」两个按钮：

- 图过期 → `搭配已更新，图还是上一版 | 更新穿搭图`
- 正在生成 → `正在更新穿搭图… | 停止等待`（上一版图继续显示，不清空）
- 生成失败 → 旧图保留，toast 说明 + 提示条可重试

## 三、部署准备情况

### 3.1 数据：哪些必须留、哪些可以丢

| 路径 | 内容 | 丢了会怎样 |
|---|---|---|
| `state.json` + `.bak` | 方案、偏好、序号 | 所有用户方案消失（`.bak` 是最后一道保险） |
| `scenes/` + `index.json` | 场景图与内容寻址索引 | 图要重新生成（**要花钱**） |
| `scenegen.usage.json` | 月度额度账本 | 预算闸门从 0 开始，可能超支 |
| `live/catalog.json` | 商品缓存 | 首次启动要重新抓店铺（慢，但不致命） |
| `chat.json` | 对话记录 | 历史对话丢失，方案不受影响 |

- 目录由 `CROSSCART_DATA_DIR` 指定（容器里是挂载卷 `/app/data-public`）；
  **没有任何一处写死 `D:/aiproject/...`**：仓库根用 `import.meta.url` 推导，数据目录用环境变量。
- 写盘是原子的：`state.json.tmp` → `state.json.bak` → rename，进程被杀不会留下半个 JSON；
  读坏时自动回退 `.bak` 并打印一行 warn（`check:p10` 的 B/C 段真起进程验证过）。
- **没有大规模迁移**：文件结构、字段、方案 ID 全部沿用，老数据直接可读。
- 为将来账号体系预留的只是**结构上的可能性**：数据目录「一层 = 一个工作区」，
  接账号时把这一层换成 `data/users/<id>/` 即可，内部文件与 `CostLedger` 都不用改（`docs/DEPLOY.md` §8.1 写明了）。
  **本轮没有 visitor id、没有用户表、没有归属字段**——没有鉴权时加 `userId` 只是假隔离。

### 3.2 密钥与环境变量

- 对话密钥：`DEEPSEEK_API_KEY` → 首次启动由 `scripts/provision-dsh-credentials.mjs` 写进 `$DSH_HOME/.credentials.yaml`（已存在则不动）。
- 生图密钥：`SCENEGEN_BASE_URL / API_KEY / MODEL` 三项齐了才算可用，缺一项如实报 `unconfigured`。
- 前端拿不到任何密钥：页面只通过 `/api/*` 读状态；`/api/demo` 公开模式只回 `{available, model}`。
- 日志不打印密钥：费用日志只有 `kind/model/amount/basis/ms/usage`（`verify:stage3` G 段断言 `sk-`/`authorization` 不出现）。
- `.env.example` 给的是清单不是真值；`.env` 不参与加载（避免「以为改了其实没生效」）。

### 3.3 限流与成本保护

| 层 | 变量 | 默认（公开模式） | 目的 |
|---|---|---|---|
| 全实例·对话 | `CROSSCART_RATE_CHAT_PER_HOUR` | 40/h | 一个人刷不光整月额度 |
| 全实例·生图 | `CROSSCART_RATE_IMAGE_PER_HOUR` | 6/h | 同上 |
| 单 IP·对话 | `CROSSCART_RATE_CHAT_PER_IP_PER_HOUR` | 12/h | 挡住单个来源 |
| 单 IP·生图 | `CROSSCART_RATE_IMAGE_PER_IP_PER_HOUR` | 3/h | 挡住连点生成 |
| 单 IP·任意 API | `CROSSCART_RATE_API_PER_IP_PER_MIN` | 90/min | 挡住脚本扫接口 |
| 单 IP·写操作 | `CROSSCART_RATE_WRITE_PER_IP_PER_MIN` | 30/min | 挡住重复提交/连点 |

- 全部在服务端判定（前端改参数没有用），超限只回「AI 对话有点频繁，请 N 分钟后再试」+ `RATE_LIMITED`，不暴露费用。
- `/api/health` 不限流（平台探针被 429 会误判实例已死）。
- 原有保护一条没动：内容寻址缓存（同组合不重复计费）、防抖合并、单飞生成、月度预算闸门（`402 BUDGET_BLOCKED`）、失败不计费。
- 管理/调试接口（`/api/scenes/budget`、`/api/catalog/refresh`、热点重算与人工修正）在公开模式默认 **404**，
  配了 `CROSSCART_ADMIN_TOKEN` 才认请求头 `x-cc-admin`。

### 3.4 部署产物

- `deploy/Dockerfile`：Node 22 + 只装生产依赖 + 构建 core + 非 root 运行 + `HEALTHCHECK` + 默认 `CROSSCART_PUBLIC=1`。
- `deploy/render.yaml`：Docker runtime + `healthCheckPath: /api/health` + 1GB 磁盘挂 `/app/data-public`。
- 启动脚本：`npm run serve:public`（无口令公网）、`npm run demo`（有口令演示）、`npm run studio`（本机开发）。
- 反向代理与 HTTPS 的 Nginx 片段写在 `docs/DEPLOY.md` 第 5 节，**关键一条是 `proxy_buffering off`**，
  否则 SSE 被缓冲，页面会「一直停在生成中」。

### 三条口径说明（都是断言写错，不是功能回归）

1. **`check:public` 的「AI 金额与方案一致」曾误报**：断言按 `plans[0]`（`pln_001`，$202）核对，
   而对话请求没带 `planId`，服务端按「最后一套方案」上下文回答（$285）。
   修法是让测试与真实界面一致——发问时带 `planId`。**没有放宽任何业务校验。**
2. **`verify:stage3` D 段的 toast flake**：换件广播的 `plan.updated` 覆盖了用户的 toast（真问题，已按第一节修）。
3. **`check:p9` 「未配置就如实 503」**：缓存命中时 `regenerate` 会直接返回缓存（正常行为），
   断言改为带 `{force:true}` 才测到「没配置 → 503」。**不是把缺配置说成成功。**

## 五、服务器部署说明（可直接照着做）

### 5.1 环境要求

- Linux x86_64（或 Render/Railway 的容器运行时），Node **22+**（Docker 镜像已内置）。
- 出网：`api.deepseek.com`（对话）、你的图像服务域名（生图）、`<店铺域名>/products.json`（商品，可离线用缓存）。
- 磁盘：至少 2GB 可用（场景图单张 60–300KB，`scenes/` 会随使用增长）。
- 一个反向代理（Nginx/Caddy）做 HTTPS。**不要用 Cloudflare 快速隧道当正式方案**（重启即换域名）。

### 5.2 方式 A：Docker（推荐）

```bash
git clone <repo> && cd crosscart
docker build -f deploy/Dockerfile -t crosscart .

docker run -d --name crosscart -p 3000:3000 \
  -e DEEPSEEK_API_KEY=sk-... \
  -e SCENEGEN_BASE_URL=https://... -e SCENEGEN_API_KEY=... -e SCENEGEN_MODEL=... \
  -e CROSSCART_TRUST_PROXY=1 \
  -v crosscart-data:/app/data-public \
  -v crosscart-dsh:/app/dsh-home \
  crosscart

curl -s localhost:3000/api/health   # {"ok":true,"version":"0.1.0"}
```

### 5.3 方式 B：不用 Docker

```bash
npm ci && npm run build
CROSSCART_PORT=3000 CROSSCART_HOST=0.0.0.0 CROSSCART_PUBLIC=1 \
CROSSCART_TRUST_PROXY=1 CROSSCART_DATA_DIR=/srv/crosscart/data \
DEEPSEEK_API_KEY=sk-... SCENEGEN_BASE_URL=... SCENEGEN_API_KEY=... SCENEGEN_MODEL=... \
node packages/bridge/src/server.mjs
```

### 5.4 Nginx + HTTPS（要点）

```nginx
location / {
  proxy_pass http://127.0.0.1:3000;
  proxy_set_header Host $host;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  proxy_buffering off;        # SSE 必须关缓冲，否则聊天/出图状态不刷新
  proxy_read_timeout 3600s;
}
```

```bash
certbot --nginx -d crosscart.example.com   # HTTPS
```

### 5.5 最小环境变量清单

```bash
CROSSCART_PORT=3000
CROSSCART_HOST=0.0.0.0
CROSSCART_PUBLIC=1
CROSSCART_TRUST_PROXY=1        # 有反向代理才设 1
CROSSCART_DATA_DIR=/app/data-public
DEEPSEEK_API_KEY=sk-...
SCENEGEN_BASE_URL=... SCENEGEN_API_KEY=... SCENEGEN_MODEL=...
# 可选：CROSSCART_ADMIN_TOKEN=...（管理接口）、CROSSCART_ACCESS_TOKEN=...（整体口令）
```

### 5.6 重启与异常退出

- `SIGINT/SIGTERM` 会先收 dsh 子进程再退出，不留孤儿占着 `$DSH_HOME`。
- 重启后从 `state.json`（或 `.bak`）恢复方案与偏好；场景图按缓存键复用，**不重复计费**。
- 正在生成的请求随进程消失 → 该方案回到「上一版图 + 待更新」，用户点一次即可。
- 建议用 `restart: unless-stopped`；健康检查探 `/api/health`。

### 5.7 公网开放前**仍然缺**的（本轮明确不做）

1. 账号体系与登录态（现在所有人共用一份数据）。
2. 数据隔离与归属权限（A 的方案/偏好对 B 可见）。
3. 每用户额度（现有额度是「整实例 + 单 IP」两层，不是账户额度）。
4. 审计日志与配额告警。
5. 备份策略（现在只有 `.bak` 单份回退，建议每日快照）。
6. 真实服务器上的压测与 SSE 长连接验证。

| 类别 | 问题 | 影响 | 建议 |
|---|---|---|---|
| 需真实环境验证 | **本机没有 Docker，镜像未真 build/run** | Dockerfile 的层、`HEALTHCHECK`、非 root 权限未在真机上跑过 | 在有 Docker 的机器执行 5.2 的三条命令；若失败看 `docker logs` |
